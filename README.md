# GridCare — Substation Management API

A Dockerized FastAPI CRUD proof of concept for managing fictional electricity distribution substations.

GridCare is an independent project inspired by the electricity distribution domain in which network operators such as UK Power Networks (UKPN) operate. It demonstrates REST API design, request validation, HTTP status handling, containerization, and API testing.

**This is an independent demonstration project. It is not affiliated with UK Power Networks and does not use live UKPN operational data.**

## Features

- REST API supporting GET, POST, PUT, PATCH, and DELETE.
- Pydantic models for request validation and response schemas.
- Automatic interactive API documentation through FastAPI.
- Docker-based application execution.
- API testing using Bruno.
- Appropriate HTTP status codes and handling of missing substations.

## Tech Stack

- **Python** — backend language
- **FastAPI** — REST API framework
- **Pydantic** — data validation and schema definitions
- **Uvicorn** — ASGI server
- **Docker** — containerization
- **Bruno** — API testing

## Architecture

Bruno / HTTP Client → FastAPI endpoints → Pydantic validation → In-memory Python list

The application currently uses in-memory storage to keep the proof of concept simple. A database has not yet been integrated.

## Substation Data Model

Each substation includes:

| Field | Description |
|---|---|
| `id` | Substation record identifier generated by the API |
| `name` | Substation name |
| `location` | Illustrative location |
| `voltage_level` | Simplified classification field using values such as `grid`, `primary`, or `secondary` |
| `status` | Operational state: `operational`, `maintenance`, or `fault` |

The current `voltage_level` field represents a simplified network classification rather than a numeric voltage measurement. Refining this into a clearly named substation type and actual voltage attributes is a potential improvement.

All sample records are fictional.

## API Endpoints

Base URL: `http://localhost:8000`

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/substations` | Retrieve all substations |
| GET | `/api/substations/{substation_id}` | Retrieve a substation by ID |
| POST | `/api/substations` | Create a substation |
| PUT | `/api/substations/{substation_id}` | Replace editable substation fields |
| PATCH | `/api/substations/{substation_id}` | Update selected fields |
| DELETE | `/api/substations/{substation_id}` | Delete a substation |

### Example: Create a substation

Send a POST request to `/api/substations` with a JSON body:

```json
{
  "name": "Eastbrook Primary Substation",
  "location": "Bromley",
  "voltage_level": "primary",
  "status": "operational"
}
```

The API returns `201 Created` and includes the generated ID.

## Run with Docker

Ensure Docker Desktop is running.

From the project root, build the image:

```bash
docker build -t gridcare-api ./backend
```

Start the container:

```bash
docker run --name gridcare-api -p 8000:8000 gridcare-api
```

Open the interactive API documentation:

http://localhost:8000/docs

To stop and remove the container:

```bash
docker rm -f gridcare-api
```

To run it again after removal, execute the `docker run` command again.

## Run Locally

From the project root:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload
```

Open http://localhost:8000/docs to explore and execute the endpoints.

## Testing with Bruno

Create a Bruno collection named `GridCare API` and configure requests against `http://localhost:8000`.

Recommended checks:

- GET returns the sample substation records.
- POST creates a record and returns `201 Created`.
- PUT replaces the editable fields of a record.
- PATCH changes only the supplied fields.
- DELETE returns `204 No Content`.
- Requests for missing IDs return `404 Not Found`.
- Invalid model values are rejected with `422 Unprocessable Entity`.

## Current Limitations

- Records are stored in memory and reset when the application restarts.
- Duplicate business records are not yet prevented.
- Authentication and authorization are not implemented.
- Automated test-suite coverage has not yet been added.
- The current data model is a simplified representation of distribution network substations.

## Potential Improvements

- Persistent storage using SQLite or PostgreSQL.
- A unique business identifier and duplicate prevention.
- Automated endpoint tests and stronger validation.
- Authentication, authorization, logging, and improved error handling.
- A React frontend for managing substations.
- A GenAI-assisted feature for generating advisory maintenance summaries from relevant asset data.
